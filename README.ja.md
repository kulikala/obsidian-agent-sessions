# Agent Sessions

**Claude Code・Codex・OpenCode を、Obsidian の vault の中のターミナルタブで動かします。**

[![Release](https://img.shields.io/github/v/release/kulikala/obsidian-agent-sessions?style=flat-square)](https://github.com/kulikala/obsidian-agent-sessions/releases)
[![License](https://img.shields.io/github/license/kulikala/obsidian-agent-sessions?style=flat-square)](LICENSE)
![Platform](https://img.shields.io/badge/platform-macOS%20%7C%20Linux%20%7C%20Windows-lightgrey?style=flat-square)

[インストール](#インストール) · [ドキュメント](docs/usage.md) · [困ったとき](#困ったとき) · [開示事項](#開示事項) · [English](README.md)

[Claude Code](https://claude.com/claude-code)・[Codex](https://github.com/openai/codex)・[OpenCode](https://opencode.ai) を、[Obsidian](https://obsidian.md) の中のターミナルタブで動かすプラグインです。vault のノートを開いたまま、隣のタブでエージェントに作業を頼めます。

![ターミナルタブで動く Claude Code のセッションと、開いているタブ・起動中・最近のセッションを並べたサイドパネル](docs/onboarding/ja/overview.png)

- **タブを閉じても、Obsidian を終了しても、セッションは止まりません。** このマシンに常駐する小さな補助プログラム（`agent-sessions`。Python で動きます）が、セッションを動かし続けます。（[起動するプログラム](#起動するプログラム)）
- **終わったセッションも、続きから再開できます。** サイドパネルでクリックすると、新しいタブで会話の続きが始まります。（[サイドパネルでのセッションの切り替え](#サイドパネルでのセッションの切り替え)）
- **すべてのセッションの状態・使用量・コストを、1 つの一覧で確かめられます。** 実行中か、入力を待っているか、終わったかがわかります。使用量とコストは、エージェントが手元に残すファイルをもとに、このマシンの中で計算します。（[ネットワーク](#ネットワーク)）

## 向いている人

エージェントに書類を書かせ、いくつもの案件を同時に進める人に向いています。たとえば、次のような人です。

- Claude Code や Codex を一日中使い、仕様書・提案書・ノートの下書きを任せている。
- 複数の案件を同時に進めていて、どのセッションが自分の返事を待っているかを知りたい。
- 書類を Obsidian で管理していて、Obsidian のエディターをターミナルの隣で使いたい。

チャット欄でエージェントと話したい人や、開いているノートをエージェントにその場で書き換えてほしい人には向いていません。このプラグインで使うのは、エージェント自身のターミナルです。モバイルだけで使う人や、Windows の Obsidian から WSL の中のエージェントを使いたい人にも向いていません（[対応環境](#対応環境)を見てください）。

## インストールで起きること

![agent-sessions のインストールダイアログ。インストール先のフォルダ、Python、Claude Code の設定に追加するフック、vault に追加する 2 つのエージェントスキルが並んでいる](docs/onboarding/ja/install.png)

プラグインは、何かをインストールする前に、上のダイアログを表示します。

- テレメトリーはなく、アカウント登録も要りません。プラグインがネットワークに接続する場面は、[ネットワーク](#ネットワーク)に挙げたものだけです。
- `~/.claude/settings.json` に、4 つのフック（Claude Code が決まった時点で呼び出すコマンド）とステータスラインを書き込みます。書き込む前にバックアップを取ります。Claude Code は、これらを通じて各セッションの状態と使用量をプラグインに知らせます。この設定は、Obsidian の外で始めたものも含め、すべての Claude Code のセッションに効きます。（[書き込むファイル](#書き込むファイル)）
- vault に 2 つのエージェントスキルを追加します。エージェントが、セッション・使用量・プラグインについての質問に答えられるようにするためです。（[書き込むファイル](#書き込むファイル)）
- 補助プログラムと、エージェントの設定に追加した項目（フックとステータスラインを含む）は、**設定 → agent-sessions プログラム → 削除** で取り除けます。（[アンインストール](#アンインストール)）

## 動作に必要なもの

- デスクトップ版の Obsidian 1.8.7 以降（macOS、Linux、Windows）。
- Python 3.9 以降。追加のパッケージは要りません。補助プログラムは Python で動きます。
- Claude Code、Codex、OpenCode のどれか 1 つ以上を、インストールしてログインしておきます。エージェントは、あなた自身の契約やキーで動きます。このプラグインのためのアカウントやキーは要りません。
- どれもまだ使ったことがなければ、先に公式ページからインストールしてください（[Claude Code](https://claude.com/claude-code)、[Codex](https://github.com/openai/codex)、[OpenCode](https://opencode.ai)）。

## 対応するエージェント

3 つのエージェントは、どれもタブで開けて、状態つきで一覧に並びます。主に違うのは、表示できる使用量です。Claude Code と Codex の契約には、5 時間ごとと 7 日ごとに使える量の上限（利用枠）があり、プラグインはその使用率も表示します。

| エージェント | タブで開く | 状態つきで一覧に並ぶ | 利用枠とコスト |
|---|---|---|---|
| Claude Code | ✅ あり | ✅ あり | ✅ あり |
| Codex | ✅ あり | ✅ あり | ✅ あり |
| OpenCode | ✅ あり | ✅ あり | コストのみ |

OpenCode には 5 時間枠も 7 日枠もないので、表示するのはコストだけです。OpenCode のサブエージェントのセッションと `opencode run` のセッションは、一覧に出ません。

## Obsidian の中で動かす理由

- エージェントには、プロンプトを外部のエディターで書くためのキーがあります（このプラグインでは既定で Ctrl+G）。このキーを押すと、外部のエディターの代わりに Obsidian のペインが開きます。`@` でファイル名を補完でき、貼り付け・元に戻す・日本語入力もふだんどおりに使えます。[詳しく](docs/usage.md#built-in-editor)
- エージェントの出力に vault のパスが出てくると、リンクとして開けます。
- セッションは普通の Obsidian のタブなので、画面を分割してノートの隣に置けます。

## 機能

### カテゴリ別のセッションと、利用状況とコスト

**セッションマネージャー** は、セッションをカテゴリごとにまとめ、5 時間枠と 7 日枠ごとのコストを示します。たとえば `ドキュメント: リリースノート` という名前のセッションは、「ドキュメント」カテゴリに入ります。セッションの一覧の下には、枠ごとに、リセットまでの時間と、今のペースで上限に届くかどうかが出ます。コストは推定値です。[詳しく](docs/usage.md#session-manager)

![セッションマネージャー。カテゴリ別のセッションとモデル・エフォート・コスト、その下に 5 時間枠と 7 日枠、カテゴリ別のコスト](docs/onboarding/ja/manager.png)

### どのエージェントでもセッションを開始

**新規セッション** を押すと、セッションの名前を聞かれます。設定で複数のエージェントを有効にしていれば、使うエージェントも選びます。Claude Code・Codex・OpenCode のセッションは、同じ一覧に並びます。[詳しく](docs/usage.md#start-a-session)

![新規セッションのダイアログ。エージェントの選択肢に Claude Code と Codex、名前に「ドキュメント: リリースノート」](docs/onboarding/ja/new-session.png)

### エージェントの CLI をそのままタブで

セッションのタブでは、エージェントのコマンドラインプログラムそのものが動きます。設定、ログイン、スラッシュコマンド、フック、スキル、MCP サーバーも、ターミナルで使うときと同じです。[詳しく](docs/usage.md#work-in-a-session-tab)

![ターミナルタブで動く Codex のセッションが、テストのコマンドを実行してよいか尋ねている](docs/images/ja/codex.png)

### サイドパネルでのセッションの切り替え

サイドパネルには、開いているタブ、タブを閉じたまま動いているセッション、最近のセッションが、状態のアイコンつきで並びます。クリックすると、セッションのタブが前に出ます。タブが無ければ新しいタブで開き、終わったセッションは会話の続きから再開します。一覧の下には、選んだセッションの状態が一文で出ます。[詳しく](docs/usage.md#switch-between-sessions)

![サイドパネル。開いているタブ・起動中・最近のセッションが状態のアイコンとカテゴリつきで並び、上に入力待ちとレビュー待ちの数](docs/onboarding/ja/side-panel.png)

### ほかの機能

- **[Remote Control](docs/usage.md#remote-control-server)**　Claude Code の機能です。サイドパネルの **rc** トグルでオンにすると、claude.ai や Claude アプリから、この vault で Claude Code のセッションを始められます。接続先は[ネットワーク](#ネットワーク)で説明しています。
- **[名前の変更とカテゴリ分け](docs/usage.md#name-and-group-sessions)**　`ドキュメント: リリースノート` のように名付けると、セッションが「ドキュメント」カテゴリに入ります。
- **[エージェントによる名前とカテゴリの提案](docs/usage.md#organize-names-and-categories)**　**セッション名とカテゴリを整理**（以下、整理）では、エージェントがセッションの名前とカテゴリを提案します。**選択を適用** を押すまで、名前は変わりません。提案するエージェントには、セッションの抜粋を送ります。送る内容は[整理で送る内容](#整理で送る内容)にあります。
- **[圧縮・再起動・モデル変更](docs/usage.md#compact-restart-and-change-model)**　セッションの ⋯ メニューから、会話を圧縮して文脈を空ける、エージェントを再起動する、別のモデルに切り替える、のどれかを行えます。
- **[利用枠を増やす](docs/usage.md#stretch-your-usage-limit)**　利用枠そのものを増やす機能ではありません。この機能では、直近の作業をエージェントが読み、トークンの無駄を探して、直し方を示します。無駄とは、たとえば会話に残ったままの大きな出力や、どのセッションも最初に同じファイルを読んでいることです。統計はこのマシンの中で計算し、外へは出しません。送るのは、あなたが始めた解析だけです。送る内容は[「利用枠を増やす」で送る内容](#利用枠を増やすで送る内容)にあります。
- **[セッション解析](docs/usage.md#session-analytics)**　1 つのセッションのコスト・トークン数・ターン数を、プロンプトごとのコストとあわせて見られます。
- **[稼働カレンダー](docs/usage.md#activity-calendar)**　どのエージェントがいつ作業していたかを、7 日の利用枠ごと・週ごと・日ごとに見られます。
- **[ようこそガイド](docs/usage.md#welcome-guide)** と 2 つの[エージェントスキル](docs/usage.md#agent-skills)　ようこそガイドは、最初の設定から順に案内します。エージェントスキルは vault に追加され、使用量、ほかのセッション（終了したものも含む）、プラグインの使い方をエージェントに尋ねられます。終了したセッションの再開、そのセッションでトークンを無駄にしたところの洗い出し、セッションの命名も頼めます。

すべての機能の説明は [`docs/usage.md`](docs/usage.md) にあります。

## 対応環境

| Obsidian | エージェント | 対応 |
|---|---|---|
| macOS | macOS | ✅ 対応 |
| Linux | Linux | ✅ 対応 |
| Windows 10（1809 以降）、11 | Windows | ✅ 対応 |
| Windows | WSL | ❌ 非対応 |
| WSL2（WSLg） | 同じ WSL ディストリビューション | ✅ 対応 |

Obsidian とエージェントは、同じ OS の上で動かしてください。プラグインがエージェントのプロセスを起動し、エージェントのファイルを読み続けるからです。エージェントを WSL で使う場合は、Obsidian も WSLg を使って WSL の中で動かします。vault は `/mnt/c` の下ではなく、WSL のファイルシステムに置いてください。

## インストール

1. Obsidian で **設定 → コミュニティプラグイン** を開きます。コミュニティプラグインがオフになっていればオンにし、**閲覧** から **Agent Sessions** を探してインストールし、有効にします。
2. ようこそガイドが開きます。補助プログラム `agent-sessions` のインストールから最初のセッションの開始まで、ガイドに沿って進めます。設定の途中で、Python と各エージェントが見つかったかどうかを表示します。見つからないものがあれば、[動作に必要なもの](#動作に必要なもの)を見てください。あとでガイドに戻るときは、コマンドパレットで **ようこそガイドの続きから** を実行します。

補助プログラムのインストール先と、ソースからインストールする方法は [`docs/installation.md`](docs/installation.md) にあります。

## 困ったとき

- **「agent-sessions が見つからない」と出る**：サイドパネルの **agent-sessions をインストール** を押します。または、プラグインの設定の **agent-sessions の場所** にプログラムの場所を入れます。
- **「agent-sessions を自分でインストールし（README を参照）」と出る**：リポジトリからインストールし（[`docs/installation.md`](docs/installation.md#from-a-clone)）、プラグインの設定の **agent-sessions の場所** に、インストールしたプログラムの場所を入力します。
- **エージェントの欄に「見つかりませんでした。」と出る**：プラグインの設定で、そのエージェントの **実行ファイル** を指定するか、ようこそガイドで **検出し直す** を押します。
- **変更した設定・フック・スキルがセッションに反映されない**：セッションの ⋯ メニューで **セッションを再起動** を選びます。
- **Windows で、インストールのダイアログに Python や Claude Code が無いと出る**：**WinGet で Python をインストール** または **WinGet で Claude Code をインストール** を押します。ユーザー単位でインストールするので、管理者の確認は出ません。
- **ARM 版 Windows で、OpenCode のタブが `bun:ffi dlopen() is not available in this build (TinyCC is disabled)` で止まる**：WinGet が入れる OpenCode の ARM64 版は、ターミナル画面を起動できません。x64 版の OpenCode を入れてください。x64 版は Windows のエミュレーションで動きます。
- **フックが `node: not found` で失敗する、またはここにない症状が出る**：[`docs/usage.md`](docs/usage.md#more-troubleshooting) の対処を見てください。

## アンインストール

1. **設定 → agent-sessions プログラム → 削除** を押します。動いているセッションを終了し、補助プログラム、エージェントの設定に追加した項目、vault のスキルを取り除きます。OpenCode の `tui.json` は、インストール前の値に戻します。`~/.claude/keybindings.json` からは、プラグインが加えたキー（`enter`、`meta+enter`、`cmd+enter`、`ctrl+enter`、`shift+enter`、`alt+enter`、`ctrl+q`、`meta+g`、`ctrl+g: null`）だけを、値が今もプラグインの設定したままのときに限って削除します。値が違うキーは残し、警告を出します。空になった `Chat` ブロックも削除します。以前あなたが設定していたキーは元に戻さず、ファイル自体も削除しません。
2. コミュニティプラグインの一覧で **Agent Sessions** を無効にし、削除します。
3. 何も残したくない場合は、`~/.agents/sessions/`、`<vault>/.agents/sessions/`、バックアップの `~/.claude/settings.json.bak-*` と `~/.codex/config.toml.bak-*` を手で削除します。Claude Code は、プラグイン自身の実行のために、`~/.claude/projects/` に空のプロジェクトフォルダも残します（[書き込むファイル](#書き込むファイル)を見てください）。名前が `-agents-sessions-organize` か `-agents-sessions-efficiency-run-current` で終わるもの、または `agent-sessions-usage-` を含むものを削除してください。

ソースからインストールした場合の手順は [`docs/installation.md`](docs/installation.md#uninstall) にあります。

## 開示事項

テレメトリーはなく、アカウント登録も要りません。プラグイン自身は、会話の中身をどこにも送りません。例外は、**セッション名とカテゴリを整理** で **提案する** を押したときと、「利用枠を増やす」で **解析する** を押したときだけです。Remote Control をオンにしたときの動きは、[ネットワーク](#ネットワーク)で説明します。タブで動くエージェントには、ターミナルで使うときと同じ権限があり、エージェントはあなたのアカウントでそれぞれのサービスに接続します。整理と「利用枠を増やす」が起動するエージェントの権限は、これより絞ってあります（[整理で送る内容](#整理で送る内容)と[「利用枠を増やす」で送る内容](#利用枠を増やすで送る内容)で説明します）。Remote Control のセッションは、あなたが選んだモードで動きます。

### ネットワーク

- プラグインと補助プログラムが自分の処理のためにネットワークへ接続するのは、Remote Control、Claude Code の `/usage`、ようこそガイドの図の読み込み、Windows のインストールのボタンだけです。どれも下で説明します。プラグインと、同じマシンに常駐する補助プログラムとのやり取りには、Unix ソケット（モード 0600。あなたのユーザーだけが開けます）を使います。Windows では、`127.0.0.1` のランダムなポートと秘密のトークンを使います。
- Remote Control は、サイドパネルの **rc** トグルでオンにしたときだけ、vault のフォルダで `claude remote-control --spawn=same-dir --permission-mode <モード>` を実行します（`same-dir` は、どのセッションもこのフォルダで始めるという指定です）。起動した Claude Code のプロセスは、Anthropic のサーバーに接続したままになります。あなたの Claude アカウントにログインしている人が claude.ai や Claude アプリから接続するたびに、vault で新しいセッションが始まります。モードは、プラグインの設定の Claude Code の欄にある **Remote Control の権限モード** で選びます。既定は auto で、Claude は確認を求めずにツールを使い、危険な操作は Claude Code の分類器（操作の危険度を判定する仕組み）が止めます。選べるモードは、default（Claude Code のふだんどおりに許可を求める）、acceptEdits、plan、auto の 4 つです。Claude Code が auto を受け付けない場合、セッションは Claude Code の既定のモード（許可を求めるモード）で動きます。初めてトグルをオンにするときと、設定を auto に変えたあと最初にオンにするときは、ダイアログで、選んだモードと、誰がセッションを始められるかを示します。auto のときは、Claude が確認なしにツールを使うことも示します。あなたが確認してから、サーバーを起動します。Obsidian やプラグインを読み込んだだけでは起動しません。Obsidian を終了してもサーバーは止まりません。サーバーは補助プログラムの常駐プロセスが動かしているためです。止めるには、トグルをオフにするか、**削除** を押します。
- Claude Code のステータスラインから利用枠の状況が分からないとき（ほかの場所で Claude を使ったときや、枠がリセットされた直後）と、利用状況の表示をクリックして更新したときは、補助プログラムが Claude Code の `/usage` を実行します。実行するのは 5 分に 1 回までです。このとき Claude Code は、アカウントの現在の利用状況を Anthropic のサーバーに問い合わせます。プロンプトやファイルは送らず、モデルも呼び出しません。
- ようこそガイドを開いているあいだは、ガイドの図を `raw.githubusercontent.com` から読み込みます。あなたのデータは送りません。GitHub には、IP アドレスと、どの図を読み込んだかが伝わります。設定の **ガイドの図を GitHub から読み込む** をオフにすると、読み込みを止められます。
- Windows で Python や Claude Code のインストールのボタンを押すと、`winget install` をそのユーザーだけに向けて実行します。WinGet は、インターネット上の配布元からパッケージをダウンロードします。ボタンを押すまでは何も実行しません。
- Remote Control を有効にして始めた Claude Code のセッション（エージェントスキルが実行する `agent-sessions new --remote-control` や、Remote Control に入っていたセッションの再開）は、`claude --remote-control=<名前>` で起動します。このプロセスも Anthropic のサーバーに接続したままになります。

### 起動するプログラム

- `agent-sessions`：このマシンにある Python で動かします。インストールを押したときにプラグインの中から書き出すもので、ダウンロードはしません。
- `claude remote-control`：**rc** トグルを押したときだけ起動します。
- `claude -p /usage --no-session-persistence`：Claude Code を有効にしているあいだ、5 分に 1 回まで実行します。MCP サーバーとユーザー設定を読まずに、空の一時フォルダで動かします。会話は保存しません。[ネットワーク](#ネットワーク)も見てください。
- Claude Code・Codex・OpenCode の CLI：インストール済みのものを、セッションを開くときに起動します。設定で OpenCode の起動方法に Ollama を選んだ場合は、`ollama launch opencode` を起動します。プラグインの設定画面では、Ollama のモデルを一覧にするために `ollama list` を実行します。
- あなたのシェル：ターミナルと同じ `PATH` を得るために、ログインシェルとして、また対話シェル（`.zshrc` や `.bashrc` を読む）として起動します。ログインシェルでは、npm で入れたエージェントを探すために、`command -v <エージェント>` と `npm config get prefix` も実行します。
- 各エージェントの `<エージェント> --version`：設定画面にバージョンを表示するために実行します。`codex --help` は、Codex が `--no-daemon` を受け付けるかを確かめるために実行します。
- `ps`：どのプロセスがどのセッションのものかを調べるために実行します。macOS では `lsof` も実行し、Codex のプロセスが開いているファイルを調べます。
- `rg`（無ければ `grep`）：Claude Code の記録から、セッション名と目標を探すために実行します。
- Windows では、`reg.exe`（`PATH` を読むため）と `py.exe`（Python を探すため）、`cmd.exe`（npm の `.cmd` 起動ファイルを実行し、空白を含むフォルダ名を短くするため）を起動します。`winget.exe` は、インストールのボタンを押したときだけ起動します。

### vault の外で読むファイル

セッションの一覧を作り、利用状況を計算するために、次のファイルを読みます。

- `~/.claude/projects/`、`~/.claude/sessions/`、`~/.claude/settings.json`
- `~/.codex/`（または `$CODEX_HOME`）
- `~/.local/share/opencode/opencode.db`（読み取り専用で開きます）

`opencode.db` を読み取り専用で開けないときは、`-wal` と `-shm` のファイルも含めて一時フォルダにコピーしてから読み、補助プログラムが閉じるときにコピーを削除します。

ここに挙げたのは既定の場所です。`~/.claude` の代わりに `$CLAUDE_CONFIG_DIR` を `settings.json` と `keybindings.json` で、OpenCode のデータベースには `$XDG_DATA_HOME` を、`~/.config/opencode/` には `$XDG_CONFIG_HOME` を、それぞれ使います。

「利用枠を増やす」では、ほかに次のものを読みます。

- 上に挙げた記録：Claude Code のセッション記録（transcript、会話のファイル）、Codex の記録（rollout、セッションのファイル）、OpenCode のデータベース。
- 各会話が最初に読み込む指示ファイルの大きさ。Claude Code の記録には、セッション開始時点の `CLAUDE.md`・`.claude/rules/`・auto memory の `MEMORY.md` の大きさと、スキルの数が残っています。Codex の記録には、読み込んだ `AGENTS.md` が残っています。OpenCode については、セッションのフォルダから Git のルートまでの各フォルダにある `AGENTS.md`（無ければ `CLAUDE.md`）と、`~/.config/opencode/AGENTS.md` の大きさを読みます。
- `$CODEX_HOME/config.toml` の最上位の `model` と `model_provider`、`$CODEX_HOME/models_cache.json` のモデル一覧。解析に使うモデルを選ぶために読みます。
- `~/.config/opencode/opencode.json` の各プロバイダの `baseURL`。このマシンで動くモデルかどうかを見分けるために読みます。
- セッションが何度も読むファイルのある、フォルダとその親フォルダ。`.git`、`CLAUDE.md`、`AGENTS.md`（Codex と OpenCode の場合）があるかを確かめ、そのファイルがどの指示ファイルの範囲にあるかを調べます。

| `~/.config/opencode/plugins/agent-sessions.js` | 状態を伝えるプラグイン | OpenCode が有効なとき |
| `~/.config/opencode/agent-sessions-tui.jsx` | ステータスライン | OpenCode が有効なとき |

| `<vault>/.agents/sessions/sessions.json` | この vault で始めたセッション（フォルダ、エージェント）、アーカイブ、カテゴリの色、折りたたんだグループ | 常に |

- `~/.claude/settings.json` と `~/.codex/config.toml` は、書き換える前にバックアップします。`tui.json` の元の値は、`~/.agents/sessions/opencode-tui-backup.json` に保存します。
- プラグインは、自分が追加した項目を、Codex・OpenCode・スキルのファイルでは書き込んだ目印で、Claude Code ではフックのコマンドで見分けます。それ以外の項目は変更しません。ただし `~/.claude/keybindings.json` に書き込むときは、`$schema` と `$docs` の項目が無ければ足し、ファイル全体を 2 文字の字下げで保存し直します。
- vault を同期している場合は、`sessions.json` も一緒に同期されます。
- Claude Code は、会話を保存しない実行でも、プラグインが実行したフォルダごとに、空のプロジェクトフォルダを `~/.claude/projects/` に残します（中にあるのは空の `memory` フォルダだけのことがあります）。「利用枠を増やす」の作業フォルダ用に 1 つ、整理の作業フォルダ用に 1 つ、`/usage` を実行するたびに 1 つ増えます。プラグインはこれらを削除しません。[アンインストール](#アンインストール)を見てください。
- 補助プログラムがインストールされうるほかのフォルダは、[`docs/installation.md`](docs/installation.md#where-the-program-goes) にあります。

### 整理で送る内容

**セッション名とカテゴリを整理** で **提案する** を押すまでは、何も送りません。押すと、プラグインはエージェントを 1 回だけ起動します。プラグインの設定で Claude Code を有効にしていれば Claude Code、そうでなければ Codex、それも無効なら OpenCode を使います。どれを使うかはダイアログに表示します。

- Claude Code：`claude -p` を Sonnet（設定で Haiku に変更可）で、ツールを使わせず、記録も残さずに実行します。
- Codex：`codex exec` を読み取り専用のサンドボックスで、ツール（シェル、Web 検索、MCP サーバー）を使わせずに実行します。
- OpenCode：`opencode run` をツールを使わせずに実行し、保存されたセッションを直後に削除します。

最大 30 件のセッション（またはセッションから開いたときは、その 1 件）について、現在の名前、フォルダ、最初のプロンプト、直近 3 つのプロンプト、最後の返答の短い抜粋を送ります。フォルダ、プロンプト、返答は、次の節の「利用枠を増やす」と同じ方法で伏せ字にします（パス、URL、メールアドレス、鍵やトークンのように見える文字列など）。現在の名前とセッション名の例は、伏せ字にせず、そのまま送ります。ほかに、今あるカテゴリ名と、カテゴリごとのセッション数、カテゴリごとに最大 3 つのセッション名の例を送ります。もう一度提案させるときは、前回の提案とあなたのコメントも送ります。送り先はエージェントのサービスで、あなたのアカウントの利用枠を消費します。

### 「利用枠を増やす」で送る内容

**利用枠を増やす…** を開いただけでは、このマシンの中で統計を計算するだけで、何も送りません。送るのは、タブで **解析する** を押したときだけです。押すと、プラグインは、解析する会話で使われていたエージェント自身を起動します。9 つの観点（[ドキュメントに一覧があります](docs/usage.md#stretch-your-usage-limit)）を 1 回の依頼でまとめて判定し、解析する期間が 1 回の依頼に収まらないときは、より短い期間に分けて順に起動します（最大 10 回）。Codex と OpenCode では、会話で最も多く使われたプロバイダの会話だけを解析し、ほかのプロバイダとの会話は対象から外します。

解析する期間は、次の順で決めます。5 時間枠の使用率が 80% 以上なら、その 5 時間枠。そうでなく 7 日枠が 80% 以上なら、その 7 日枠。どちらでもなければ、新しい呼び出しから換算トークン（入力・出力・キャッシュのトークンを 1 つの尺度にそろえた量）が 10,000,000 に達するまで。ただし、最低でも直近 24 時間、最大で 7 日までさかのぼります。80%（50〜95%）と 10,000,000（1,000,000〜100,000,000）は、設定の **利用枠のしきい値** と **予算** で変えられます。

- Claude Code：`claude -p` を Sonnet（設定で Opus に変更可）で、ツールを使わせず、記録も残さずに実行します。
- Codex：`codex exec` を読み取り専用のサンドボックスで、ツールを使わせず、rollout も残さずに実行します。モデルは、Codex があなたのアカウントに提供しているモデル（`$CODEX_HOME/models_cache.json`）のうち、最新の世代のモデルを使います。Sol、Terra、Luna は Codex のモデルの 3 つの階層で、モデル ID の末尾（`…-sol`、`…-terra`、`…-luna`）で見分けます。Sol のモデルを使い、無ければ Terra、Terra も無ければ Luna を使います。Codex がモデルを受け付けないときは、同じ世代の次の階層、1 つ前の世代、`config.toml` のモデルの順に試します。モデル一覧が無いときは、`config.toml` のモデルだけを使います。ローカルのプロバイダ（Ollama、LM Studio）では、期間の中で最も多く使われたモデルを使います。
- OpenCode：`opencode run` を、ツールを使わせずに、会話のプロバイダと、期間の中で最も多く使われたモデルで実行します。実行に使ったセッションは、終わったあとに削除します。プロバイダがこのマシンで動いている場合（Ollama、LM Studio、`baseURL` がこのマシンを指す場合）は、ローカルのモデルで解析するので、データはマシンの外に出ません。

会話を別のエージェントや別のプロバイダに送ることはありません。各タブの統計にも、タブのプロバイダのセッションだけが入ります。**解析する** の上の **詳細** を開くと、押す前に、送り先とおおよその量、依頼の回数がわかります。**詳細** の中の **送るものを見る** では、各回に送る文字列をそのまま確かめられます。

送るのは、解析する期間のすべての作業を、数値と短い抜粋にまとめたものです。

- **送るもの**：伏せ字にしたセッション名とフォルダ、期間全体の合計、指示ファイルの大きさとスキルの数、統計で目立った箇所。ターン（あなたのプロンプト 1 つと、それに対するエージェントの作業）ごとに、プロンプト（最大 600 字）、エージェントの返答の冒頭（200 字）、ターンの数値（トークン数、種類ごとのツール呼び出し回数、読んだ・検索した・編集したパス、中断、途中の待ち時間、かかった時間、文脈の大きさ、キャッシュの再書き込み、モデル）。
- **送らないもの**：ツールの出力とファイルの中身。
- **伏せ字にするもの**：パス、URL（URL に含まれるユーザー名とパスワードも）、メールアドレス、鍵やトークンのように見える文字列。パスは末尾の 2 要素までを残し、vault の中のパスは vault からの相対パスにします。URL はホスト名だけを残します。ホームフォルダとユーザー名は、どの OS の形式のパスに含まれていても、単独のフォルダ名として現れても置き換えます。
- **量**：1 回の依頼は最大 60,000 字です。収まらないときは期間で区切って最大 10 回に分けます。それでも収まらなければプロンプトを短くし、さらに古い作業から外します。
- **節約できる量**：直したときに節約できるトークン数は、エージェントではなくプラグインが記録の数値から計算します。
- **動かす場所**：空のフォルダ `~/.agents/sessions/efficiency-run/current/` の中で動かします。このフォルダは解析のたびに作り直し、終わると削除します。ただし Claude Code は、解析用の空のプロジェクトフォルダを `~/.claude/projects/` に 1 つ残します。
- **残るもの**：統計のキャッシュには、会話の文字列は入りません。直近 2 回の結果は、伏せ字にした引用とともに、あなたが消すまで `~/.agents/sessions/efficiency/` に残ります。
- **使うアカウント**：ローカルのモデルで解析する場合を除き、送り先はエージェントのサービスで、あなたのアカウントの利用枠を消費します。

解析で見つかった問題のうち、ファイルや設定で直せるものには **エージェントに直してもらう** があります。押しても、vault で新しいセッションを始めるだけです。依頼文は、セッションを始める前に読んで書き換えられます。セッションは、変更の前に確認を求める状態で始まります。Claude Code は plan モード（変更案を示し、承認を待つ）、Codex は書き込む前に承認を求める読み取り専用のサンドボックス、OpenCode は `plan` エージェントで始めます。プラグイン自身はファイルを書きません。

### その他のアクセス

- vault のファイル一覧：内蔵エディターで `@` のパスを補完するときだけ読みます。
- クリップボード：セッション ID、解析の表、Remote Control の接続リンクをコピーするときと、macOS 以外でターミナルタブの Ctrl+Shift+C または Ctrl+Shift+V を押したときだけ使います。
