# Agent Sessions

[Claude Code](https://claude.com/claude-code)・[Codex](https://github.com/openai/codex)・[OpenCode](https://opencode.ai) を、ノートの隣のターミナルタブで動かす [Obsidian](https://obsidian.md) のプラグインです。エージェントのセッションを1か所に並べ、それぞれの状態、利用枠、推定の利用額を表示します。

![ターミナルタブで動く Claude Code のセッションと、開いている・実行中・最近の Claude Code と Codex のセッションを並べたサイドパネル](docs/images/overview.png)

## できること

### エージェントは、そのままの CLI としてターミナルタブで動きます

1つのセッションは、Obsidian のタブで動くエージェントのコマンドラインプログラムです。ターミナルで起動するものと同じプログラムです。スラッシュコマンド、プランモード、許可の確認、フック、スキル、MCP サーバーは、いつもの設定とログインのまま使えます。出力に出たファイルパスのうち、vault の中を指すものはリンクとして開けます。タブのヘッダーのボタンで、開いているノートを `@path` として入力できます。

タブを閉じても、Obsidian を終了しても、セッションは動き続けます。開き直すと最後の画面が表示され、続きから作業できます。

![承認待ちの Codex のセッションと、別のタブの Claude Code のセッションが終わったことを知らせる通知](docs/images/codex.png)

### 複数のセッションを同時に。グループと状態で見分けられます

- 複数のセッションを並行して動かせます。Claude Code・Codex・OpenCode のセッションが同じ一覧に並びます。
- 各セッションには、作業中、回答待ち、未読の返答あり、完了のどれかが表示されます。タブ、サイドパネル、**セッションマネージャー**で同じアイコンを使います。別のタブのセッションが終わったときや質問してきたときは、通知が出ます。
- セッションに `カテゴリ: 名前` の形で名前を付けると、グループにまとまります。セッションマネージャーは、グループを並べ替えのできる表で示し、状態で絞り込めます（入力待ち、レビュー待ち、実行中、完了、アーカイブ済み）。
- **セッション名とカテゴリを整理**は、最近のセッションの会話の内容から、名前とカテゴリを提案します。提案には、インストール済みのエージェントを1つ使います。提案は1件ずつ確認でき、**選択を適用**を押すまで名前は変わりません。

![セッションマネージャー：カテゴリ別のセッションと枠ごとの利用額、その下に5時間枠と7日枠の利用状況](docs/images/manager.png)

![セッション名とカテゴリを整理のダイアログ：セッションごとに提案されたカテゴリと名前](docs/images/organize.png)

### 利用状況、利用額、稼働カレンダー

- エージェントごとの5時間枠と7日枠を、リセットまでの残り時間とともに表示します。今のペースで週の上限に届くかどうかの見通しも出ます。OpenCode には利用枠がありません。
- セッションごと・カテゴリごとの推定利用額を表示します。**セッション解析結果**では、1つのセッションのトークン、ツールの使用、利用額をターンごとに確認でき、Markdown としてコピーできます。利用額は、エージェント自身のトランスクリプトから手元のマシンで計算した推定値です。
- **稼働カレンダー**は、各エージェントが作業していた時間を、日ごとのブロックで示します。表示の単位は7日枠・週・日から選べます。ブロックをクリックすると、その中のプロンプトを確認でき、セッションを開けます。

![稼働カレンダー：1週間のセッションを色付きのブロックで並べ、日ごとにエージェント別のレーンと、エージェントごとの時間と同時実行数を表示](docs/images/calendar.png)

### はじめ方と、ふだんの使い方

- 初めてインストールすると、**ようこそガイド**が開きます。Python とエージェントを確認し、書き込む内容を一覧で示してから補助プログラムをインストールします。そのあと、実際にセッションを始め、タブを切り替え、名前を変え、プロンプトを送るところまで、1手ずつチェックしながら進めます。
- **内蔵エディタ**（Ctrl+G）は、入力中のプロンプトをターミナルの下の枠で開きます。`@` でファイル名を補完でき、貼り付け、取り消し、日本語入力もふつうに使えます。出力は見えたままです。
- **モデルを変更…**で、動いている Claude Code のセッションのモデルと effort を切り替えられます。**セッションを再起動**は、エージェントを再起動して、同じタブで同じ会話を続けます。エージェントの設定やスキルを変えたあとに使います。
- vault に2つのエージェントスキルが追加されます。エージェントに、利用状況や他のセッションのこと、プラグインの使い方を尋ねられます。

![ようこそガイド](docs/images/welcome.png)

すべての機能は [`docs/usage.md`](docs/usage.md) にあります。

### できないこと

- チャットパネルはありません。開いているノートをその場で編集する機能もありません。エージェントはターミナルタブで動きます。
- デスクトップ専用です（Obsidian のモバイル版では使えません）。
- **モデルを変更…**は Claude Code だけで使えます。Windows で使えるのは Claude Code だけです。
- OpenCode のサブエージェントのセッションと、`opencode run` で始めたセッションは一覧に出ません。

## プライバシー

- プラグインは、自分の処理のためにネットワークを使いません。例外はようこそガイドで、開いているあいだ図を GitHub から読み込みます。設定で止められます。エージェントは、ターミナルで使うときと同じく、あなたのアカウントでそれぞれのサービスに接続します。
- テレメトリーはなく、アカウントも不要です。MIT ライセンスのオープンソースです。
- エージェントの設定ファイルには、プラグイン自身の項目を足すだけです（Claude Code と Codex の設定は先にバックアップします）。プログラムを削除すると、その項目だけを取り除きます。
- エージェントの権限は、ふだんのターミナルで使うときと同じです。
- セッションの文章をモデルに送るのは、**セッション名とカテゴリを整理**だけです。送り先はあなた自身のエージェントで、ボタンを押したときだけ送ります。

ネットワーク、ファイル、起動するプログラムの一覧は[開示事項](#開示事項)にあります。

## 動作に必要なもの

- Obsidian 1.8.7 以降のデスクトップ版。
- macOS、Linux、Windows（Windows は Claude Code のみ）。
- Python 3.9 以降。追加のパッケージは要りません。Windows では、インストールのダイアログから WinGet で入れられます。
- Claude Code・Codex・OpenCode のうち、少なくとも1つがインストール済みであること。

## インストール

1. Obsidian で **設定 → コミュニティプラグイン → 閲覧** を開き、**Agent Sessions** を検索して、インストールし、有効にします。
2. ようこそガイドが開きます。案内に沿って補助プログラム `agent-sessions` をインストールし、最初のセッションを始めます。ガイドは閉じても、コマンドパレットの**ようこそガイドの続きから**で戻れます。

プログラムのインストール先と、ソースからのインストールは [`docs/installation.md`](docs/installation.md) にあります。

## 対応環境

| 構成 | 対応 | 確認状況 |
|---|---|---|
| macOS | 対応 | macOS 26.6（Python 3.14）でスモークテストに合格（15 ステップ中 15） |
| Linux（Ubuntu Desktop） | 対応 | Ubuntu 24.04（カーネル 6.8、Python 3.12）でスモークテストに合格 |
| Windows ①：Windows 版 Obsidian ＋ Windows 版 Claude Code | 対応（Claude Code のみ） | Windows 11 ビルド 26300（Python 3.13）でスモークテストに合格 |
| Windows ②：Windows 版 Obsidian ＋ WSL1 内の Claude Code | 非対応 | — |
| Windows ③：Windows 版 Obsidian ＋ WSL2 内の Claude Code | 非対応 | — |
| Windows ④：WSL2 内の Linux 版 Obsidian（WSLg）＋ WSL2 内の Claude Code | 動く見込み | 未確認。手順は [`docs/testing.md`](docs/testing.md#4-platform--checks) |

スモークテストは 2026-10-04 に、arm64 の仮想マシン上で、Obsidian 1.13.7 とテスト用のエージェントを使って実施しました。確認する内容は [`docs/testing.md`](docs/testing.md) にあります。Windows 10 1809 以降でも動くはずですが、確認していません。Windows では、Codex と OpenCode の設定に「Windows ではまだ使えません。」と表示されます。

プラグインとエージェントは、同じ OS の上で動く必要があります。② と ③ では、エージェントのファイルとプロセスが WSL の中にあり、プラグインからセッションを始めたり追ったりできません。WSL でエージェントを使う場合は、Obsidian も WSL の中で動かしてください（④）。理由は [`docs/principles.md`](docs/principles.md#4-supported-platforms-are-the-ones-where-agent-and-plugin-share-an-os) にあります。

## 困ったとき

- **「agent-sessions was not found」と出る**：補助プログラムがまだインストールされていません。サイドパネルの **agent-sessions をインストール** を押してください。自分でインストールした場合は、プラグインの設定でその場所を指定してください。
- **エージェントが検出されない**：プラグインの設定で、そのエージェントのパスを指定してください。ようこそガイドの**検出し直す**でも探せます。
- **設定・フック・スキルの変更がセッションに反映されない**：セッションの ⋯ メニューから**セッションを再起動**を使ってください。
- **Windows で Python や Claude Code が無い**：インストールのダイアログから WinGet で入れられます。ユーザー単位のインストールで、管理者の確認は出ません。
- `node: not found` で失敗するフックなど、その他の場合は [`docs/usage.md`](docs/usage.md#more-troubleshooting) にあります。

## アンインストール

まず **設定 → agent-sessions プログラム → 削除** を開きます。動いているセッションが終了し、プログラムがエージェントの設定に足した項目と、vault に足したスキルが取り除かれ、プログラムが削除されます。そのあと、コミュニティプラグインで **Agent Sessions** を無効にして削除します。ソースからインストールした場合は [`docs/installation.md`](docs/installation.md#uninstall) を見てください。

## 仕組み

プラグインは、小さな Python のプログラム `agent-sessions` を、読めるソースのまま同梱しています（標準ライブラリのみ）。インストールのボタンを押すと、これを書き出します。その常駐プロセス（デーモン）が各セッションのターミナル（PTY。Windows では ConPTY）を持ち、ローカルのソケットでプラグインとやりとりします。そのため、タブが無くても、Obsidian を閉じていても、セッションは動き続けます。セッションの一覧、状態、利用状況、利用額は、エージェント自身のトランスクリプトと状態ファイル（読むだけです）、そしてプログラムがエージェントに足すフックとステータスラインから得ています。タブのターミナルは xterm.js で描いています。設計は [`docs/principles.md`](docs/principles.md)、[`docs/design.md`](docs/design.md)、[`docs/architecture.md`](docs/architecture.md) にあります。

## 開示事項

**ネットワーク。** プラグインとプログラムは、自分の処理のためにネットワークへ接続しません。プラグインは同じマシンのデーモンと Unix ソケット（モード 0600）でやりとりします。Windows では `127.0.0.1` のランダムなポートを使い、クライアントは最初に秘密のトークンを送る必要があります。例外として、ようこそガイドを開いているあいだは、図を GitHub（`raw.githubusercontent.com`、プラグインのバージョンに固定）から読み込みます。あなたのデータは送りません。GitHub には IP アドレスと、どの図を求めたかが伝わります。設定の**ガイドの図を GitHub から読み込む**で止められます。Claude Code・Codex・OpenCode は、あなたのアカウントでそれぞれのサービスに接続します。

**起動するプログラム。**
- `agent-sessions` プログラムを、マシンにある Python で動かします。プログラムはインストールのボタンを押したときにプラグインから書き出すもので、ダウンロードはしません。
- インストール済みの Claude Code・Codex・OpenCode の CLI（選んだ場合は `ollama launch opencode`）。ターミナルと同じ `PATH` を得るため、ログインシェルも起動します。
- Windows では、`reg.exe`（`PATH` を読むため）と `py.exe`（Python を探すため）をコンソールなしで起動します。`winget.exe` は、インストールのボタンを押したときだけ起動します。

**vault の外で読むファイル**（セッションの一覧と利用状況のため）：`~/.claude/projects/`、`~/.claude/sessions/`、`~/.claude/settings.json`。`~/.codex/`（または `$CODEX_HOME`）。OpenCode のデータベース `~/.local/share/opencode/opencode.db`（読み取り専用で開きます）。

**vault の外に書くファイル。**
- `~/.agents/sessions/`：デーモンのソケット、ログ、状態ファイル、キャッシュ。
- プログラム自身のフォルダー（`~/.local/share/agent-sessions`、Windows では `%LOCALAPPDATA%\agent-sessions`。詳細は [`docs/installation.md`](docs/installation.md#where-the-program-goes)）。
- `~/.claude/settings.json`：4つのフックと `statusLine`。先にバックアップします。`~/.claude/keybindings.json`：送信キーかエディタキーを既定から変えたときだけ。
- Codex が有効なとき、`~/.codex/config.toml`：送信キー、エディタキー、既定のステータスライン。先にバックアップし、足した行には印を付けます。
- OpenCode が有効なとき：状態プラグイン `~/.config/opencode/plugins/agent-sessions.js` とステータスライン `~/.config/opencode/agent-sessions-tui.jsx`。どちらにも印を付け、印のあるファイルだけを上書きします。また `~/.config/opencode/tui.json` に、エディタキー、送信キー（送信キーを変えたときだけ）、`plugin` の一覧へのステータスラインの項目を書きます。`tui.json` の元の値は `~/.agents/sessions/opencode-tui-backup.json` に保存し、OpenCode をオフにしたときやプログラムを削除したときに戻します。
- エージェントが内蔵エディタに渡す一時ファイル。

**vault の中に書くファイル。** `<vault>/.agents/sessions/sessions.json`（アーカイブ、カテゴリの色、折りたたんだグループ）。プログラムをインストールすると、`agent-sessions` と `agent-sessions-help` の2つのスキルを `<vault>/.claude/skills/`（Claude Code）と `<vault>/.agents/skills/`（Codex）に書きます。OpenCode はこの両方を読みます。OpenCode だけが有効なときは `<vault>/.opencode/skills/` に書きます。スキルのファイルには `agent-sessions:managed` の印があり、印の無いファイルは変更しません。

**取り除き方。** **設定 → agent-sessions プログラム → 削除**（または `agent-sessions setup --remove`）で、上に挙げたもののうちプログラムが足した項目とファイルを取り除き、OpenCode のキー設定を元に戻し、vault からスキルを削除します。

**整理で送る内容。** **セッション名とカテゴリを整理**で**提案する**を押すと、プラグインはエージェントを1回だけ起動します。Claude Code（`claude -p`。既定は Sonnet、設定で Haiku も選べます。ツールは使わず、トランスクリプトも残しません）、無ければ Codex（`codex exec`、読み取り専用のサンドボックス）、それも無ければ OpenCode（`opencode run`。保存されたセッションは直後に削除します）を使います。どのエージェントを使うかは、先にダイアログに表示されます。最大30件のセッション（または選んだ1件）について、フォルダー、最初のプロンプト、あなたが入力した最後の3つのプロンプト、最後の返答の短い抜粋を送ります。あわせて、既存のカテゴリ名と、カテゴリごとに最大3つのセッション名の例を送ります。再提案のときは、前回の提案とあなたのコメントも送ります。送り先はそのエージェントのサービスで、あなたのアカウントの利用枠に数えられます。ボタンを押すまで、何も送りません。

**その他のアクセス。** vault のファイル一覧は、内蔵エディタで `@` のパスを補完するときだけ読みます。クリップボードは、セッション ID や解析結果の表をコピーするときと、ターミナルタブで Ctrl+Shift+C / Ctrl+Shift+V を押したとき（macOS 以外）だけ使います。
